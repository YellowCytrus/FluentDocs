## S1. Схлопывание отступов

Файл: `spikes/S1-weak-spacing.typ`.

Критерий: одна пустая строка между таблицей и заголовком; два слабых отступа не
суммируются; жёсткие суммируются; слабый отступ на верху страницы не даёт зазора.

Команда:

```bash
typst compile S1-weak-spacing.typ /tmp/S1.pdf
```

Измерение (pdfplumber, координаты `top`/`bottom`, pt):

| Место | Значение |
|---|---|
| верх страницы до `TOP-MARK` | 55.01 (поле 2 см = 56.7 pt, лишнего зазора нет) |
| `TABLE-A` bottom → `WEAK` top | 34.63 (ожидание 12 мм = 34.02 pt; два слабых 6+12 мм не суммировались) |
| `TABLE-B` bottom → `HARD` top | 51.64 (ожидание 18 мм = 51.02 pt; жёсткие суммировались) |

Результат: пройден. Решение: в `fd` пустая строка реализуется через
`v(..., weak: true)`, `collapse = "max"` получается бесплатно; `collapse = "none"`
строится на жёстких `v()`/`block(above/below)`.

## S2. Продолжение/окончание таблицы

Файл: `spikes/S2-table-continuation.typ`.

Критерий: на первой странице таблицы метки нет, на средних — «Продолжение таблицы 1»,
на последней — «Окончание таблицы 1»; шапка повторяется.

Команда:

```bash
typst compile S2-table-continuation.typ /tmp/S2.pdf
```

Вывод (pdfplumber, 4 страницы, 120 строк):

| Страница | Первая строка |
|---|---|
| 1 | `№ Показатель Значение` |
| 2 | `Продолжение таблицы 1` |
| 3 | `Продолжение таблицы 1` |
| 4 | `Окончание таблицы 1` |

Результат: пройден. Решение: метки `metadata(none) <t-start>` и `<t-end>` вокруг
таблицы, диапазон страниц читается через `query(...).first().location().page()`
в `page.header`. В `fd` нужны две метки на таблицу и шаблоны меток из профиля.

## S3. Двойная линия под шапкой

Файл: `spikes/S3-table-double-line.typ`.

Критерий: под шапкой две горизонтальные линии с зазором; конструкция повторяется
на каждой странице продолжения.

Команда:

```bash
typst compile S3-table-double-line.typ /tmp/S3.pdf
```

Вывод: на обеих страницах горизонтальные линии шапки на y = 73.93 и 75.35 pt,
зазор 1.42 pt (0.5 мм); далее строки таблицы.

Результат: пройден. Решение: `table.hline` + `table.cell(colspan, v(0.5mm),
stroke: none)` + `table.hline` внутри `table.header`. Параметры (толщины, зазор)
выносятся в опции реестра.

## S4. Перенос формулы

Файл: `spikes/S4-formula-break.typ`.

Критерий: длинная формула переносится по знаку операции, знак повторяется на новой
строке; желателен автоматический перенос.

Команда:

```bash
typst compile S4-formula-break.typ /tmp/S4.pdf
```

Вывод: Typst не разрывает формулы автоматически и не выдаёт предупреждение.
40 слагаемых дают правую границу 853.7 pt при ширине страницы 595.3 pt, то есть
формула уходит за поля. Ручной `\` и помощник
`#let eq-break(op) = linebreak() + op` работают: вторая строка начинается со знака `+`.

Результат: частично. Автоперенос невозможен на Typst 0.14.2.
Решение владельца (B-01, решено): принят fallback — ручной разрыв формулы `\`
в Markdown; помощник `fd.eq-break` не делаем. На G5 нужен UI-разрыв и/или
предупреждение о переполнении.

## S5. Что проходит через Pandoc

Вход: `spikes/S5-pandoc-input.md`.
Выходы: `spikes/S5-pandoc-server-3.9.typ`, `spikes/S5-pandoc-wasm-3.9.typ`.

Команды:

```bash
pandoc --from=markdown+raw_attribute --to=typst S5-pandoc-input.md
node <скрипт с convert({from:'markdown+raw_attribute',to:'typst'}, md)>
```

Наблюдения (сервер и wasm, Pandoc 3.9):

| Конструкция | Результат |
|---|---|
| `# Заголовок {-}` | `#heading(level: 1, numbering: none)[...]` — работает |
| рисунок `![...](...){#fig:x width=50%}` | `#figure(image(...), caption: [...])` + `<fig:x>` |
| таблица с `: caption {#tbl:y}` | `#figure(... table ... kind: table)` + `<tbl:y>` |
| `[@fig:x]`, `[@tbl:y]` | `@fig:x`, `@tbl:y` — Typst-ссылки на существующие метки компилируются |
| `$$...$$ {#eq:z}` | `$ ... $ {\#eq:z}` — метка формулы потеряна, ссылка не работает |
| fenced div `::: {#note .warning data-role="box"}` | `#block[...] <note>` — сохранён только id как метка, классы и data-атрибуты потеряны |
| ` ```{=typst} ... ``` ` | сырой Typst вставлен как есть |
| обычный fenced code | ` ```python ... ``` ` |

Сравнение версий: `diff -u S5-pandoc-wasm-3.9.typ S5-pandoc-server-3.9.typ`
не даёт различий (`diff_exit=0`). Обе версии — Pandoc 3.9.

Результат: пройден. Решение: сервер зафиксирован на Pandoc 3.9 (B-02 решён);
расширения Markdown не вводим сверх разрешённого п. 2.10 (только подпись
таблицы/формулы через `: Подпись`).

## S5b. Подпись формулы через двоеточие

Вход: `spikes/S5b-formula-caption.md`.
Выход Pandoc 3.9: `spikes/S5b-pandoc-3.9.typ`.
Перехват в Typst: `spikes/S5b-formula-caption.typ`.

Критерий: строка `: Подпись` после `$$…$$` даёт подпись формулы по шаблону;
обычные списки определений не ломаются.

Команда:

```bash
pandoc --from=markdown+raw_attribute --to=typst S5b-formula-caption.md
typst compile S5b-formula-caption.typ /tmp/S5b.pdf
```

Вывод Pandoc 3.9:

```typst
/ $ E = m c^2 $: #block[
Подпись формулы
]

/ $ a^2 + b^2 = c^2 $: #block[
Вторая подпись
]

Обычный список определений:

/ Термин: #block[
Определение термина
]
```

Перехват в Typst: `#show terms.item: it => ...` проверяет
`it.term.func() == math.equation`; для формулы шагает собственный счётчик
и выводит `formula-caption(formula-n.display("1"), it.description.body)`,
для остальных возвращает исходный `terms.item`.

Текст PDF:

```text
1 Формулы
E = mc²
Формула 1 — Подпись формулы
a² + b² = c²
Формула 2 — Вторая подпись
Обычный список определений:
Термин
Определение термина
```

Результат: пройден. Решение: на G5 подпись формулы перехватывать в Typst
через `terms.item`, шаблон брать из реестра (тот же, что у таблиц и рисунков).

## S9. Калибровка межстрочного интервала

Файл: `spikes/S9-line-pitch.typ`.

Критерий: множитель `m` даёт расстояние между базовыми линиями
`m * natural_line_height`.

Измерения (pdfplumber, Libertinus Serif 14 pt, разные `leading`):

| leading | Расстояние между базовыми линиями |
|---|---|
| 0 | 9.21 pt |
| 0.65em | 18.31 pt |
| 1.3em | 27.41 pt |
| 2.6em | 45.61 pt |

Отсюда `natural_line_height = 1.308em` и
`fd.line-pitch(m) = (m * 1.308 - 0.658) * 1em`.

Проверка:

| m | Измерено | Ожидание `m * 18.31` | Отклонение |
|---|---|---|---|
| 1.0 | 18.31 | 18.31 | 0.00 |
| 1.5 | 27.47 | 27.465 | +0.005 |
| 2.0 | 36.62 | 36.62 | 0.00 |

Результат: пройден. Решение: множитель хранить числом, перевод в `leading` — одна
функция. Коэффициент естественной высоты строки (`1.308` для Libertinus Serif)
является свойством шрифта: в G2 он должен браться из данных реестра, из таблицы
«шрифт → коэффициент», а не быть константой в коде. Для других шрифтов требуется
отдельная калибровка и запись в таблицу.

## S10. Ненумерованный заголовок по тексту

Файл: `spikes/S10-unnumbered-heading.typ` (исходный прототип), реализация —
`app/typst/fd.typ`, `heading-content`.

Критерий: «Введение»/«Заключение» без номера; следующие заголовки сохраняют
сквозную нумерацию; в `#outline()` ровно одна запись на заголовок.

Команда:

```bash
typst compile S10-unnumbered-heading.typ /tmp/S10.pdf
```

Первоначальный прототип компенсировал счётчик через показ-правило
`show heading`, что давало второй заголовок и дубли в оглавлении. В G3a
механизм переделан: заголовки собираются один раз проходом по
верхнеуровневым элементам тела (`body-units`). Для `numbering.mode = "none"`
заголовок и все его подразделы выводятся с `numbering: none`; `counter(heading)`
не меняется. Для `own` и приложений номер считается в проходе по телу
(локальные счётчики семейств/уровней) и выводится в теле заголовка при
`numbering: none`, поэтому `#outline()` получает тот же текст. Временной
правки `counter(heading)` нет, предупреждения `layout did not converge` нет.

Вывод G3a для `none` + `##` (`tests/test_g3a_structural.py`):

```text
Введение
Подраздел
Текст подраздела.
1 Раздел
Текст раздела.
```

Результат: пройден. `0.1` отсутствует; счётчик `continue` после `none`
продолжается с `1`; проверки —
`test_structural_unnumbered_subheading_has_no_zero_prefix` и
`test_appendix_numbering_subheadings`.

## S12. Политики столкновения вставок на 600 элементах


| Проверка | Значение |
|---|---|
| Элементов | 600 |
| Страниц | 36 |
| Typst CLI | 0.281 с |
| `typst.ts` (`typst-parity.mjs`) | 292 мс |
| Размер PDF `typst.ts` | 199 665 байт |
| Текст PDF (pdfplumber) | совпал, SHA-256 `47cbe669e421b935…`, 29 374 символа |

Результат: пройден. Проход по телу не замедляет компиляцию заметно, `typst.ts`

`figure(kind: table)`, вид остальных фигур — `figure`.

## S13. Оглавление: один авторитетный заголовок

Файл: `spikes/S13-outline-single-entry.typ`.

Критерий: `outlined: false` убирает запись из `#outline()`, `numbering: none`
даёт запись без номера, номер в теле сохраняется, следующий раздел получает
номер 1, а не 2; на каждый заголовок ровно одна запись.

Команда:

```bash
typst compile S13-outline-single-entry.typ /tmp/S13.pdf
pdftotext -layout /tmp/S13.pdf -
```

Вывод:

```text
Contents
1 Раздел .......... 1
  1.1 Подраздел ... 1
3 Второй .......... 1

Введение
Текст введения.
1 Раздел
Текст раздела.
1.1 Подраздел
Текст подраздела.
2 Скрытый
Текст скрытого раздела.
3 Второй
Текст второго раздела.
```

Результат: пройден. «Введение» без номера и не сдвигает счётчик; «Скрытый»
есть в теле с номером 2, но не в оглавлении; «Второй» — 3. Записей ровно
столько, сколько заголовков с `outlined: true`. Решение: пересобирать
заголовки проходом по телу и не использовать второй `heading` внутри
`show heading`.
