## 1. Принципы

1. **«Без хардкода» = параметризованный код.** Логика под аспект форматирования может быть в коде, но управляется значениями из профиля, где уместно — отключаема, и у каждой опции есть обоснование.
2. **Сущность с триггером вместо особого случая** (пример: «Введение» срабатывает по подстроке в заголовке).
3. **До/после каждого элемента — настраиваемая вставка** (пустые строки с заданным интервалом, произвольный текст со своим шрифтом, линия, разрыв страницы).
4. **Алиасы живут в Typst.** Pandoc — и на сервере, и в браузере — вызывается без фильтров (`markdown+raw_attribute → typst`); это единственный общий знаменатель, поэтому вся логика оформления идёт в Typst-слое.
5. **Только PDF через Typst.** DOCX не трогаем.

## 2. Дефолтный профиль СФУ (задача 1)

Сейчас его нет: `ProfileRepository.create(name)` создаёт пустой профиль, значения берутся из дефолтов моделей (`style_defaults.py`), и они не соответствуют СТУ. Примеры: поля 25 мм со всех сторон против 30/20/10/20 (СТУ 7.1.2); межстрочный интервал 5,08 мм (абсолютный) против «1,5»; нумерация страниц `none`; нумерация заголовков `1.1.1` без разделения структурных элементов.

Дефолтный профиль СФУ — это seed-данные, а не код: набор значений реестра (раздел 3.1), создаваемый при инициализации и клонируемый пользователем. Для каждой опции в seed лежит значение и ссылка на пункт СТУ.

## 3. Целевая архитектура

### 3.1. Реестр правил (вариант Б)

| Поле | Зачем |
|---|---|
| `id`, `group`, `applies_to` | адрес опции, к какому элементу относится |
| `type`, `unit`, `allowed_units`, `min/max/step`, `enum` | тип, единицы (мм каноничны), диапазон |
| `default_sfu` | значение в seed-профиле СФУ |
| `enabled_default`, `depends_on` | опциональность и зависимости |
| `ui` | контрол, подпись, подсказка, место во вкладках |
| `rationale` | обязательное обоснование |
| `source` | пункт СТУ и/или id правила `tupoi_word` |

Хранение: JSONB с версией схемы. Из реестра выводятся: схема валидации, форма UI (замена ручного `styleFields.ts` — сейчас 973 строки дублируют модель), seed, конфиг для Typst.

Что уже есть и переиспользуется: единицы измерения (мм каноничны, конвертация в UI через `unitConversion.ts`, `allowedUnits` в описании поля); `text_override` как общий механизм шрифтовых настроек; `numbering_enabled` по уровню заголовка.

### 3.2. Typst-рантайм

Преамбула сейчас — Python-строки по одному блоку на элемент (`build_typst_preamble`); логика есть только у подписей рисунков (Python генерирует счётчики Typst). Цель: библиотека `fd` на Typst + конфиг профиля в виде словаря, вставляемого в начало исходника (литерал), без `--input` и внешних файлов, чтобы `typst.ts` в браузере и Typst CLI на сервере исполняли один и тот же текст. Риск — скорость превью; проверяется прототипом S8.

### 3.3. Примитивы

| Код | Примитив | Что покрывает |
|---|---|---|
| P1 | Реестр опций | схема, UI, валидация, seed |
| P2 | Базовые set/show-параметры | шрифт, размер, цвет, выравнивание, интервалы (в т. ч. относительные), отступы, переносы |
| P3 | **Окружение элемента** (до/после) + схлопывание | пустые строки, вставляемый текст/линии, разрывы страниц. Идея: «пустая строка» = слабый вертикальный отступ Typst (`weak`); соседние слабые отступы схлопываются до наибольшего и пропадают на границе страницы — решает «две пустые строки подряд». Подтвердить S1 |
| P4 | **Сопоставитель** (триггер → стиль) | структурные заголовки, приложения, список сокращений, абзац «где…», реферат |
| P5 | **Движок нумерации** | шаблоны `{section}.{n}`, `{letter}.{n}`, область сброса, алфавиты с исключениями, режим «приложение» |
| P6 | Подписи | шаблон, позиция, выравнивание, разделитель, метки продолжения; сегодня только у рисунков |
| P7 | Таблицы | сетка по сторонам, двойная линия шапки, повтор шапки, метки продолжения, курсив букв |
| P8 | Списки | маркер по уровням, висячий отступ, кириллическая нумерация, запись списка источников как абзац |
| P9 | Страницы и секции | размер, ориентация, поля по ориентации, нумерация (в т. ч. пропуск/смещение), секции другого формата |
| P10 | Оглавление | глубина, отступы по уровням, регистр, группировка приложений, авто-пропуск |
| P13 | Синтаксис расширений Markdown | конструкции, которых нет в Markdown (приложение А) |
| P14 | Тесты паритета | превью ↔ PDF на эталонных документах |

Вне плана: шаблонные страницы (canvas), библиография, рамки.

## 6. Что уже есть и дефекты (по коду `dev`)

**Есть:** профиль → стили по элементам (страница, документ, абзац, заголовок + уровни 1–6, списки, таблица, рисунок, сноска, цитата, код, термины, оглавление, формула) с CRUD; `text_override`; мм как каноническая единица (миграции `convert_style_units_to_mm`, `convert_table_style_lengths_to_mm_float`); `numbering_enabled` и `break_before` по уровню заголовка; шаблон подписи рисунка; живое превью `pandoc-wasm` + `typst.ts`; PDF через Pandoc CLI → Typst CLI; изоляция SFU-титула через `#page(...)[...]`.

**Дефекты и риски:**

1. **Мёртвые поля заголовков** `outlined`, `bookmarked`, `offset` остаются в ORM, Pydantic и UI; генератор их не использует (комментарий в коде). Вы решили убрать: сначала скрыть в UI/API, колонки удалить вместе с переходом на реестр.
2. **Превью без титула, PDF с титулом.** `Editor.vue` в `dev` совпадает с версией из `main`: превью собирает `преамбула + тело`. Для показа с плейсхолдерами они должны проходить через тот же генератор (`generate_fragment`), а он серверный.
3. **Межстрочный интервал** хранится как абсолютный `leading` в мм, а правило СТУ — «1,5». Нужен относительный режим.
4. **`show figure.caption` без фильтра по виду фигуры** — подписи таблиц, вероятно, пройдут через шаблон рисунков (проверить).
5. **Дефолт ширины рисунка 4,23 мм** (бывшее «1em») — проверить, не даёт ли миниатюры.
6. **Нет seed-профиля СФУ** (раздел 2).
7. **Алиас шрифта** TNR → Libertinus Serif, а не PT Astra Serif.
8. Pandoc без фильтров: любой Lua-фильтр нарушит паритет, если не работает в `pandoc-wasm` (S5).
9. Из `Plans.md` остаются: висячие отступы списков, кириллическая нумерация, регистр заголовков, отступ первой строки заголовка, переполнение таблиц, наследование стиля во вложенных списках.

## 7. Волны и прототипы

**Волна 0 — страховка и фундамент.**
- Набор эталонных документов + профиль и снимок текущего Typst-вывода; сравнение «до/после» на каждом шаге.
- Реестр (P1) рядом со старыми таблицами, чтение из обоих источников; миграция элементов по одному, старый генератор остаётся, пока новый не даёт идентичный вывод.
- Тест паритета превью/PDF (P14); seed-профиль СФУ (раздел 2).
- Прототипы: **S1** слабые отступы как схлопывающаяся пустая строка; **S2** метки «Продолжение/Окончание таблицы»; **S3** двойная линия под шапкой; **S4** автоперенос формул; **S5** что проходит через `pandoc-wasm` (атрибуты, div'ы, фильтры); **S6** пропуск оглавления при ≤ N страниц; **S7** кириллическая нумерация параметризуемой функцией; **S8** время компиляции превью с рантаймом `fd` на 100+ страниц; **S9** относительный межстрочный интервал vs Word-«1,5».

**Волна 1 — «дешёвые» параметры (P2, P9):** страница, поля, шрифт, интервалы (с относительным режимом), отступы, переносы, кегль таблиц, сноски; чистка мёртвых полей.

**Волна 2 — окружения и сопоставитель (P3, P4):** до/после с схлопыванием; структурные сущности (введение, заключение, содержание, список источников как заголовок, список сокращений, приложение).

**Волна 3 — нумерация и подписи (P5, P6):** рисунки/таблицы/формулы по разделам и приложениям, буквенные приложения, шаблоны подписей (и для таблиц, формул).

**Волна 4 — таблицы и оглавление (P7, P10).**

**Волна 5 — расширения Markdown (P13), формулы, ссылки внутри документа.**

Зависимости: P1 → всё; P2/P3 → P5–P7; P5 → P6, P10; P13 → P6, P7.
